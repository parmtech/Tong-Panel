# Site catalog details preview

The Sites list can open read-only details for a selected site through the existing `GET /api/v1/sites/{siteID}` handler. Each request is authorized by the server for the current tenant and session. The panel displays the tenant-relative document root and recorded primary/alias ownership states as text. These are catalog metadata, not evidence of current DNS control, installed hosting or a certificate.

The client limits response bodies to 16 KiB, validates the selected site and returned fields, and ignores canceled or stale responses. Closing details, refreshing or paging the list, tab hiding and focus loss clear the panel. An explicit 401/403 clears the visible site list and generated Nginx preview as well. As with other read-only previews, the client cannot detect an unseen session change while the page stays focused; the server checks authorization on every request. No site, DNS or host mutation is performed.

The selected-site panel can load read-only database catalog metadata through the existing tenant/session-authorized database list endpoint. Database IDs, generated database names and generated usernames are metadata only; they do not establish that MariaDB databases or users exist. The client requests pages of up to 50 entries and rejects responses above 64 KiB rather than truncating. Changing site, closing details, refreshing the list, hiding the tab or losing focus clears and invalidates pending data. Explicit 401/403 clears the visible site and database metadata. No database or user is created, and no password is displayed.

Database catalog supports optional `page=1` with `limit` from 1 to 50 and an exclusive `after` database ID; omitting query parameters preserves the legacy unpaged API. Each page rechecks current tenant membership and session in the same database snapshot as the rows. Pages are ordered by database ID and are not a cross-request snapshot: concurrent changes can cause missed or repeated entries. The explorer displays one page at a time, keeps at most 100 cursor positions, and resets when the selected site changes. Database entries remain metadata and do not establish provisioning.

The Sites list supports a literal, case-sensitive site ID prefix (up to 63 ASCII letters, digits, underscores or hyphens). Submitting the filter restarts pagination; each page sends the same prefix and independently rechecks current tenant/session authority. Underscore is a literal character, not a SQL wildcard. It searches site IDs only, not domains, and pages are not a snapshot under concurrent changes.
