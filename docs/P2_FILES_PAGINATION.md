# Files listing pagination (development API)

The existing `GET /api/v1/files` behavior remains unchanged: the directory must fit the requested `limit`, or the endpoint returns 413. Clients can opt in to pagination with `page=1` and a `limit` from 1 to 1000. The response adds `next_after`; an empty string means no further page. To continue, send that value as the `after` query parameter with the same path and `page=1`. URL-encode it as a query value; it is a filename, not a filesystem path or authorization credential. Authentication, `files:read` authorization and server-selected tenant roots still apply to every request.

Each page re-reads and sorts the directory by filename bytes. It is not a snapshot: changes between requests may cause entries to be missed or repeated; restart the listing for a fresh view. A concurrent deletion may produce a short or empty page with a nonempty continuation. Clients must follow `next_after`, rather than treating a short page as the end. Symlinks are listed without being followed.

Each request scans at most 10,000 directory names, including internal staging names. Larger directories fail with 413 rather than yielding incomplete results. A name that is not valid UTF-8 or contains a backslash or ASCII control character fails the request rather than issuing a cursor the explorer cannot use. Enumeration is bounded but still incurs a full scan for each page; this is not a scalable indexed directory or a consistent snapshot. Existing daemon/backend enablement and production/security gates are unchanged.

The explorer provides Previous and Next controls and re-fetches each page. Refresh and folder navigation restart at page 1. Cursor history is limited to 100 pages; a failed page request leaves the last successful page available. Results remain subject to the concurrent-change limitations above.

The read-only explorer offers a text preview for regular files up to 256 KiB. The browser reads the existing tenant-scoped content endpoint with a hard streaming limit, strictly decodes UTF-8 and renders text as text, never as HTML. Binary/control data and larger files are refused. Navigation, refresh, closing the preview, focus loss and tab hiding clear its contents and invalidate outstanding responses. Existing session authorization applies when fetching; the UI cannot detect an otherwise unseen server-side session or tenant change while the page remains focused, so this preview is not a live authorization monitor.

The explorer can filter the current folder by a case-sensitive filename prefix, using `prefix` with `page=1`. This is not recursive search. The prefix is limited to 128 UTF-8 bytes, must not contain separators or ASCII controls, and must accompany every continuation request; submitting a new filter restarts pagination. Matching occurs only after the full bounded name scan, so the 10,000-name cap and concurrent-change caveats still apply. Changing folders resets the filter. A 401 or 403 clears the displayed file rows, pagination and preview; transient failures retain the last successful same-folder listing.
