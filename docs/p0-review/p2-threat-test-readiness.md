## How to read the evidence

- **Design** means a requirement or test idea in the repository; it is not an implemented safeguard.
- **Reported test evidence** means a phase checkpoint or helper inventory reports a test/CI result. Unless an exact immutable code revision and run are identified below, this packet has not independently rerun or authenticated it.
- **Component evidence** means a primitive or isolated fixture was exercised. It does not prove the end-to-end boundary works.
- **Integrated evidence** would cover the panel request, authorization, durable job, privileged boundary, operating-system effect and observable audit result under the hostile case. No such complete P1-to-host acceptance is established by the sources reviewed here.
- **Missing** means no qualifying evidence was located in the reviewed baseline and helper reports; it is not proof no test exists elsewhere.

The canonical [threat model](../THREAT_MODEL.md) is titled “Initial, Unreviewed,” [security blueprint](../SECURITY.md) states design requirements only, and [test strategy](../TEST_STRATEGY.md) is planned. The roadmap requires review/approval of architecture ADRs, a fixed P1 scope and support matrix, and explicit go/no-go before P0 exits. The [P0 phase plan](../phases/P0-PLANNING.md) separately requires each high-impact threat to map to an issue/test contract, reviewed mitigation and responsible workstream. None is satisfied by this draft alone.

## Priority test contracts proposed for the P0 reviewer

These are proposed contracts for the accountable owners/reviewers to accept, revise or reject; none is claimed executed here:

1. **T01/T08 public browser boundary:** exercise login, MFA/recovery, cookie issue/rotation/logout, CSRF/origin, trusted-proxy spoofing, TLS assumptions, throttling, audit and session revocation against the actual HTTP routes; include malformed, stale and concurrent attempts.
2. **T02 authorization at effect time:** two tenants × roles × object operations × job lifecycle. Include cross-tenant guessed IDs for get/list/export/mutate, role revocation after enqueue, tenant reassignment attempts, duplicate/replayed jobs, worker restart and post-restore sessions. Assert both no disclosure and no host-side effect.
3. **T03 privileged operation contract:** fuzz the typed protocol; reject unknown verbs, fields, paths, identities, tenant/job bindings, expired/replayed requests and oversized input. Prove no shell invocation or arbitrary path/command path; verify audit record and effect are linked. Require an independent reviewer before any privileged verb is accepted.
4. **T04 file/archive denial matrix:** `..`, absolute paths, separator variants, symlink/hardlink escape, rename/TOCTOU races, archive traversal, duplicate entries, decompression bomb, special files, quota overflow, disk-full and interrupted atomic write. Run in an isolated disposable filesystem/VM and verify other tenants/root remain unchanged.
5. **T05/T07 hostile code and catalogue:** defer acceptance until P3/P5 scope is explicit; before enabling, attempt host mount/socket access, credential reads, forbidden network, resource exhaustion, malicious manifest/update, digest/signature substitution and rollback/revocation.
6. **T06 secret lifecycle:** inject canary secrets into every supported source (request, environment, provider response, command output, DB, backup, error/log/attachment); verify authorized use, redaction, rotation/revocation and denied key-loss/wrong-key recovery. Do not use real credentials in tests or this packet.
7. **T09/T13 service-specific failures:** test unowned domain, stale/mismatched challenge, DNS propagation timeout, renewal failure, webhook replay, provider credential revocation, relay unauthenticated send and unavailable upstream; keep optional P4 functionality out of the supported matrix until accepted.
8. **T10/T15 recovery and crash:** corrupt, oversized, truncated and malicious archives; wrong/missing/revoked keys; duplicate/reordered restore; full disk and process termination at each durable boundary; retry/reconcile and restore to clean host with two tenants. Verify no source-session resurrection and no cross-tenant data exposure.
9. **T11/T12 install and host safety:** in disposable clean VMs only, wrong signature/hash/key/architecture, unsupported distro, port conflict, firewall/SSH survival, interrupted package installation, failed health check and rollback. Never use a production host as a test target.
10. **T14 future remote agents:** enrollment, least authority, mTLS rotation/revocation, network partition, stale/replayed job, tenant/resource mismatch and return-to-service reconciliation before any multi-server gate.

Every accepted test contract should state owner/workstream, issue, interface, exact threat ID, accepted control, command/script, immutable commit, OS/architecture/profile, expected negative result, reviewer, logs/artifact location with secrets redacted, and exclusions. Unit tests, local CI and prototype checks should remain explicitly labeled at their actual layer.
