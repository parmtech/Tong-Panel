# P2 Safe File Access Prototype

**Status:** isolated Linux-only prototype in draft PR #35. It is not an API, file manager, tenant authorization layer, or production filesystem service.

## Contract

- `files.OpenRoot` pins a configured directory descriptor and refuses a symlink at the final root component. The configured root and its parent path must be administrator-controlled.
- `Root.ReadFile` accepts only a normalized relative path, opens beneath the pinned root with Linux `openat2`, and forbids symlinks, magic links, and crossing nested mount points. No fallback is attempted if the kernel does not support the required syscall/resolution flags.
- `Root.ListDir` returns a sorted snapshot with a caller-selected bound (at most 1,000 entries). Empty path selects the pinned root. Symlinks appear only as names and are never followed; listing through symlinked directories fails closed. Concurrent changes may make the snapshot incomplete.
- `Root.WriteNew` creates a new regular file inside a random mode-0700 staging directory at the pinned root, then uses `renameat2(RENAME_NOREPLACE)` into the destination directory. This prevents a tenant-writable destination directory from swapping the temporary source path. It uses mode 0600, caps content at 16 MiB, and never overwrites an existing file or symlink. A parent-directory sync error can occur after the rename, in which case the file may be present while durability remains unknown.
- `Root.RemoveFile` unlinks only regular-file or symlink directory entries and never follows a symlink; directories and special files are rejected. A successful unlink followed by parent-directory sync failure means the path may already be absent while durability remains uncertain. The operation is not an ACL or per-user object ownership decision.
- `Root.ExtractGzipTarNew` accepts a new target directory only. It rejects traversal, absolute and duplicate names, symlinks, hardlinks, devices, FIFOs, and other special entries; it applies no archive ownership or permission metadata. Files are mode 0600 and directories mode 0700. Entries are staged in a private mode-0700 directory and published with atomic no-replace rename. Default upper limits are 32 MiB compressed, 80 MiB expanded, 16 MiB per file, 64 MiB total regular-file data, and 2,048 entries/nodes; callers may lower but not raise them. A process crash may leave an orphan staging directory. A parent/root sync error after publication can mean the target is present while durability is uncertain. The API caller must also bound the request body before allocating the input byte slice.
- A process crash can leave a private archive staging directory. `CleanupStaleArchiveStages` and its `TenantRoots` wrapper are explicit cleanup primitives, not yet wired into startup. It only considers exact internal names, requires the effective UID and private directory permissions, keeps stages younger than one hour, and skips a directory with an active exclusive `flock`. It removes contents without following symlinks. Generic file operations reject these reserved root names, and root listings hide them.
- `TenantRoots` copies a fixed server-owned tenant-to-root mapping, rejects closed or inode-aliased roots, and selects only the assigned root for reads, listings, create-only writes, file removal, and bounded archive extraction. The caller must supply a tenant identifier derived from a verified server principal; this helper does not authenticate or authorize that principal.
- Reads are limited to 16 MiB maximum, and only regular files are returned. FIFOs and devices are not treated as readable file content.
- `Close` is synchronized with reads; reads after close fail.
- The package is not wired to HTTP, the privileged agent, site identities, quotas, or ACLs. It must not be represented as cross-tenant file access control.

## Tests

Linux tests cover parent traversal, absolute/non-normalized paths, symlink and root-symlink rejection, directory/FIFO inputs, byte limits, close behavior, tenant-root selection for reads/listings/writes/removal, unknown-tenant denial, duplicate-root rejection, atomic create-only writes, concurrent single-winner creation, and concurrent reads/writes while an attacker repeatedly swaps paths for symlinks to an outside secret. Successful operations must never expose or change outside-root fixture data; kernel errors are expected to fail closed.

## Remaining P2 work

This primitive does not satisfy the P2 Files UI/API or end-to-end two-tenant isolation gate. `WriteNew` supports creation only; safe file removal exists without authorization or ownership integration; update/replacement, upload quotas, archive extraction over HTTP, update/replacement policy, file metadata policy, orphan staging cleanup, and concurrent-edit semantics are not implemented. `ListDir` is an untrusted-content snapshot primitive, not an authorization decision or stable transactional view. Archive extraction supports only gzip-compressed tar and is not connected to an HTTP upload, scanner, ACL or user/object ownership policy. The tenant mapping is not an authorization boundary until integrated with reviewed identity policy. The phase still depends on reviewed P1 identity/job/host-agent boundaries, installer and supported-OS lab, service adapters, scoped ACLs/quotas, and end-to-end restore/security evidence. No host mutation or deployment is included.
