# Tong Panel — Threat Model (Initial, Unreviewed)
**Status:** DRAFT; requires security review in issue #2.  
**Risk frame:** likelihood x impact, not claimed penetration-test evidence. No production component exists yet.

## Assets
Linux host root access; system configs; customer's web content and app secrets; tenant database/mail credentials; domain DNS records and cert keys; customer backup archives; remote agent identities; release signing keys; audit records; session tokens.

## Actors
Anonymous attacker on the Internet, compromised user account, malicious tenant app, compromised marketplace recipe, untrusted package mirror, malicious insider/reseller, leaked OAuth token, compromised VPS and supply-chain attacker.

## System trust boundaries
1. Internet -> TLS -> unprivileged web/API.
2. Browser session -> API auth -> scoped resources and jobs.
3. Job queue -> host agent Unix socket -> OS services.
4. User upload/build -> per-site sandbox/paths.
5. Panel -> DNS, mail relays, backups, Git provider, ACME.
6. Local controller -> remote worker agents (future).
7. Signed releases -> installer/OS package manager.
8. Logging/support bundles -> human administrators.

## Threat register
| ID | Attack / failure | Likely impact | Mandatory mitigation | Evidence before relevant phase |
|---|---|---|---|---|
| T01 | API authentication bypass / session theft | total panel access | MFA, session revoke, CSRF/secure cookies, rate limiting, TLS, recovery audit | auth integration and abuse tests P1 |
| T02 | Cross-tenant IDOR / background job privilege bug | customer data exposure | every resource scope check at request AND job/agent; immutable tenant ownership | negative authorization matrix P1/P2 |
| T03 | Command injection to root agent | full host compromise | typed allowlist; no shell interpolation; local peer identity; safe args | fuzz + static review P1 |
| T04 | Symlink/path/archive extraction escape | other tenants' files or root configs | directory-fd operations/openat2 where available, canonical relative paths, safe extraction and quota | malicious upload and race tests P2 |
| T05 | Malicious Git build / runtime escape | secrets and host compromise | isolated build UID/network/cgroup, no host root mounts/docker socket | hostile app tests P3 |
| T06 | OAuth/Git token or backup key leak | code/data compromise | scoped credentials, envelope encryption and rotation, redacted logs | leakage/redaction tests P1/P3 |
| T07 | Malicious marketplace plugin / update | root persistence | manifest signing, permission grants, reviewed recipes, pinned digests and rollback | registry/adversarial tests P3/P5 |
| T08 | CSRF/SSRF/webhook replay | unauthorized mutations, internal network reach | CSRF/origin validation, outbound allowlist, signed webhook nonce/timestamp | endpoint tests P1/P3 |
| T09 | DNS hijack / SSL challenge mismatch | site takeover/false HTTPS | ownership validation, cert status verification, scoped provider tokens | failed issuance/renewal tests P2/P4 |
| T10 | Backup/archive restore bomb | disk exhaustion and data overwrite | limits, safe staging, schema validation, dry run, signatures, offsite copies | fail/recovery drills P2/P4 |
| T11 | Package supply-chain swap or compromised installer | host-root malware | signed immutable releases, offline verify, mirror provenance, no unverified remote script | install signature tamper tests P1/P6 |
| T12 | Host firewall/SSH lockout | irreversible remote outage | dry-run, snapshot, connection survival checks and rollback journal | clean VM injection P2/P6 |
| T13 | Mail open relay or spam abuse | blacklisting/financial/legal impact | authenticated submission, rate limits, relay and MX/SPF/DKIM/DMARC checks | SMTP abuse tests P4 |
| T14 | Remote agent hijack (future) | multiple server compromise | scoped one-time enrollment, mTLS cert revocation, per-job authorization | partition/revocation tests P5 |
| T15 | Full disk, power/network failure mid-job | inconsistent service/data loss | durable idempotent jobs, atomic stage/apply/revert, capacity reserve, recovery journal | fault injection P1/P2/P6 |

## Immediate review questions
- Which precise Unix peer auth mechanism and socket ownership are portable across tested distros?
- What capability system prevents a job generated by a tenant A API call from acting on tenant B resources?
- How will filesystem operations resist symlink swaps and archive extraction escapes without elevated web API rights?
- Are tenant app builds allowed external networking by default, and how are proxies or Git providers isolated?
- What protected offline backup of release signing keys and key rotation process exists?
- Who is able to declare a vulnerability disclosure contact? Must not invent a mailbox.
- What service and OS profiles stay out of initial threat scope?

## Threat-model exit gate
Each high-impact threat above must have a corresponding issue/test contract, reviewed mitigation and a responsible workstream. Draft table alone does NOT constitute threat mitigation or passed security evaluation.
